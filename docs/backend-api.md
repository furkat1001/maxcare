# MaxCare — API сервера (спринт 1)

Базовый адрес в разработке: `http://localhost:8080`. Все тела — JSON. Ошибки возвращаются как
`{"error": "<код>"}`; текст для пользователя приложения подбирают сами по коду.

| Код ошибки | HTTP | Когда |
| --- | --- | --- |
| `invalid_request` | 400 | Неверный JSON или поля |
| `email_taken` | 409 | E-mail уже зарегистрирован |
| `invalid_credentials` | 401 | Неверный e-mail или пароль (что именно — не уточняется) |
| `invalid_code` | 400 | Код привязки неверный, истёк или уже использован |
| `not_found` | 404 | Устройства нет или оно чужое (не различаются) |
| `unauthorized` | 401 | Нет или истёк токен сессии родителя |
| `rate_limited` | 429 | Превышен лимит запросов |

## Родитель

### `POST /v1/parents` — регистрация
```json
{"email": "parent@example.test", "password": "минимум 8 символов"}
```
→ `201 {"parentId": "<uuid>"}`. Лимит: 5 в час с одного адреса.

### `POST /v1/sessions` — вход
Тело то же. → `201 {"token": "<токен сессии>"}`, действует 30 дней.
Дальше передаётся в заголовке `Authorization: Bearer <токен>`.
Лимит: 10 попыток за 15 минут на пару «адрес + e-mail».

### `POST /v1/sessions/google` — вход через Google
```json
{"idToken": "<ID-токен от Google Sign-In>"}
```
→ `201 {"token": "<токен сессии>"}` — та же сессия, что и при входе по паролю.

Сервер сам проверяет токен по открытым ключам Google: подпись RS256, срок, издатель
(`accounts.google.com`) и получатель — один из ID клиентов в `MAXCARE_GOOGLE_CLIENT_IDS`
(через запятую; пусто — вход через Google выключен и всегда `401`). Дальше:

1. Этот пользователь Google (`sub`) уже входил — тот же аккаунт, даже если сменился e-mail.
2. Иначе есть аккаунт с тем же e-mail и Google подтвердил адрес (`email_verified`) — Google
   связывается с ним; пароль продолжает работать.
3. Иначе создаётся новый аккаунт без пароля (войти по паролю в него нельзя).

| Ответ | Когда |
| --- | --- |
| `401 invalid_credentials` | Токен поддельный, просрочен, выдан другому приложению или вход не настроен |
| `409 email_taken` | Адрес занят аккаунтом с паролем, а Google его не подтвердил |
| `400 invalid_request` | В токене нет e-mail — новый аккаунт не создать |
| `404 not_found` | Неизвестный провайдер (`/v1/sessions/apple` — пока тоже) |

Лимит: 20 попыток за 15 минут с одного адреса.

### `GET /v1/account` — аккаунт и пробный период (родитель)
```json
{
  "email": "parent@example.test",
  "createdAt": "2026-10-09T10:00:00Z",
  "hasPassword": true,
  "providers": ["google"],
  "plan": {"status": "trial", "trialEndsAt": "2026-10-23T10:00:00Z", "trialDaysLeft": 14}
}
```
`providers` — связанные входы (`google`, позже `apple`); `hasPassword: false` — аккаунт создан
входом через Google и пароля нет.

Пробный период — у семьи, 14 дней с регистрации (`families.trial_ends_at`; продлить семье —
поменять это поле). `trialDaysLeft` округляется вверх: остался час — это ещё 1 день.
`status`: `trial` или `expired`. Оплаты пока нет: после окончания ничего не блокируется,
статус только показывается.

## Привязка телефона ребёнка

### `POST /v1/pairing-codes` — код привязки (родитель)
```json
{"childName": "необязательно, до 64 символов"}
```
→ `201 {"code": "12345678", "expiresAt": "2026-10-09T10:10:00Z"}`. Код одноразовый, живёт 10 минут.
Лимит: 20 в час на родителя.

### `POST /v1/devices/pair` — привязка (телефон ребёнка, без токена)
```json
{"code": "12345678", "deviceName": "до 64 символов", "platform": "android"}
```
→ `201`:
```json
{"deviceId": "<uuid>", "deviceToken": "<токен устройства>", "recoverySecret": "<base64, 32 байта>"}
```
`deviceToken` и `recoverySecret` выдаются **один раз**: телефон сохраняет их в зашифрованном
хранилище. На сервере токен хранится как SHA-256, секрет — зашифрованным (AES-256-GCM).
Лимит: 10 попыток за 10 минут с одного адреса.

### `DELETE /v1/device` — отвязка (телефон, `Authorization: Bearer <deviceToken>`)
→ `204` без тела. Сервер удаляет устройство и всё, что о нём собрано: события, маршрут, время
в приложениях, ограничения. Ребёнок пропадает из списка родителя, место в лимите детей
освобождается. Токен после этого не действует (`401`).

Телефон вызывает отвязку только после того, как родитель отключил защиту паролем, и затем
стирает свои данные целиком. Ответ `401` на отвязку телефон считает успехом: сервер этот токен
уже не знает, удалять нечего.

## Код восстановления

### `POST /v1/devices/{deviceId}/recovery-code` (родитель)
→ `200 {"code": "87654321", "validUntil": "2026-10-09T10:10:00Z"}`.
Лимит: 10 в час на родителя.

Если родитель забыл пароль, он получает код здесь и вводит его на телефоне ребёнка.
Телефон проверяет код **без сети** тем же алгоритмом:

- TOTP по RFC 6238 с HMAC-SHA256, 8 цифр;
- ключ — `recoverySecret` из ответа на привязку (32 байта после base64);
- счётчик — `floor(unix_time / 300)` (интервал 5 минут);
- телефон принимает код текущего и предыдущего интервала, то есть код действует 5–10 минут;
- каждый счётчик принимается не больше одного раза (телефон запоминает последний использованный).

Эталонные значения для проверки реализации — RFC 6238, приложение B (SHA-256, 8 цифр);
тест сервера: `backend/src/test/kotlin/.../RecoveryCodesTest.kt`.

## События защиты и «телефон на связи»

Только факты: что и когда. Никакого содержимого экрана, переписки или файлов.

| `type` | Когда |
| --- | --- |
| `admin_disabled` | Администратор устройства отключён не через приложение |
| `protection_disabled` | Родитель отключил защиту паролем |
| `password_lockout` | 5 неверных паролей подряд, ввод заблокирован |
| `password_recovered` | Пароль сброшен кодом восстановления |
| `notifications_off` | Уведомления MaxCare Kids выключены (один раз на каждое выключение) |
| `device_booted` / `device_shutdown` | Телефон включён / выключается |
| `vpn_off` | Фильтр сайтов выключен не через приложение (другой VPN, отключение в настройках) |
| `private_dns_on` | Включён «Частный DNS» с адресом сервера — запросы идут мимо фильтра |
| `site_blocked_filtered` | Заблокирован взрослый или вредоносный сайт (семейный DNS-провайдер); адрес — в `detail` |
| `site_blocked_gambling` | Заблокирован сайт ставок или азартных игр; адрес — в `detail` |
| `location_off` | Геолокация телефона выключена — маршрута нет |
| `location_denied` | У MaxCare Kids отозван доступ к геолокации (в том числе «в фоне») |
| `location_on` | Геолокация снова работает после `location_off` или `location_denied` |

`detail` — уточнение для родителя, сейчас только адрес **заблокированного** сайта (например,
`m.example.com`): его пометил фильтр, поэтому он передаётся (CLAUDE.md). Адреса остальных сайтов
телефон не отправляет. Сервер принимает `detail` только как обычное доменное имя до 253 символов;
иное отбрасывается, а событие сохраняется.

### `POST /v1/device/events` (телефон, `Authorization: Bearer <deviceToken>`)
```json
{"events": [{"id": "<uuid с телефона>", "type": "site_blocked_filtered", "occurredAt": "2026-10-09T07:30:00Z", "detail": "m.example.com"}]}
```
→ `200 {"accepted": 1}` — сколько событий новых.

- От 0 до 100 событий. **Пустой список — отметка «на связи»**: телефон шлёт её раз в 15 минут,
  пока защита включена. Каждый запрос обновляет `lastSeenAt`.
- Повторная отправка тех же `id` безопасна — дубли не сохраняются.
- Неизвестный `type` пропускается, а не отклоняет пачку: новая версия приложения со старым сервером
  не должна застревать.
- `occurredAt` — по часам телефона и принимается как есть, даже из будущего; рядом сервер хранит
  своё время получения (`receivedAt`).
- Лимит: 120 запросов в час на устройство.

### `GET /v1/devices/{deviceId}/events` (родитель)
```json
{"lastSeenAt": "2026-10-09T10:15:00Z",
 "events": [{"type": "admin_disabled", "occurredAt": "2026-10-09T10:14:58Z", "receivedAt": "2026-10-09T10:15:00Z"}]}
```
Последние 100 событий, новые первыми. `lastSeenAt: null` — телефон ещё ни разу не выходил на связь.

`?from=2026-10-08T19:00:00Z&to=2026-10-09T19:00:00Z` — события, **случившиеся на телефоне** в этом
промежутке (`to` не включается), до 500, новые первыми: так лента дня берёт свой день по часовому
поясу родителя. Оба параметра или ни одного, ISO-8601, `from < to`, промежуток не длиннее 26 часов;
иначе `400 invalid_request`.

**Как читать «нет связи».** Если `lastSeenAt` давно не обновлялся, приложение удалено, телефон
выключен или нет интернета — сервер их не различает. Подсказка — последнее событие: `device_shutdown`
означает, что телефон, скорее всего, просто выключен. Порог тревоги выбирает приложение родителя
(ориентир — 6 часов: в режиме сна Android откладывает отметки).

## Время в приложениях

Сколько минут каждое приложение было на экране за календарный день (по местному времени телефона).
Только название и время — что ребёнок делал внутри приложения, не передаётся (CLAUDE.md).

### `POST /v1/device/app-usage` (телефон, `Authorization: Bearer <deviceToken>`)
```json
{"days": [{"date": "2026-10-15",
           "apps": [{"packageName": "com.google.android.youtube", "label": "YouTube", "foregroundMs": 2400000}]}]}
```
→ `200 {"accepted": 1}` — сколько дней сохранено.

- Каждый присланный день **заменяется целиком**: телефон шлёт снимок за последние 3 дня раз
  в 15 минут, поэтому повтор безопасен, а очередь на телефоне не нужна.
- До 7 дней в запросе, дата — не позже завтра и не раньше чем 7 дней назад по часам сервера (UTC);
  до 300 приложений в дне, без повторов `packageName`; `foregroundMs` от 0 до суток;
  `label` не пустой, до 100 символов. Любая ошибка отклоняет весь запрос (`400 invalid_request`).
- Каждый запрос обновляет `lastSeenAt`. Лимит: 60 запросов в час на устройство.

### `GET /v1/devices/{deviceId}/app-usage?date=2026-10-15` (родитель)
```json
{"date": "2026-10-15", "updatedAt": "2026-10-15T09:45:00Z",
 "apps": [{"packageName": "com.google.android.youtube", "label": "YouTube", "foregroundMs": 2400000}]}
```
Приложения по убыванию времени. `updatedAt` — когда пришёл последний снимок дня; `null` и пустой
список — за день данных нет. Без `date` или с неверной датой — `400`; чужое устройство — `404`.

## Ограничение времени в приложениях

Правила родителя для одного телефона. Телефон считает время и блокирует сам, сервер только
хранит набор. Когда срабатывает блокировка, телефон присылает событие `app_limit_reached`.

```json
{"rules": [{"kind": "group", "target": "video", "dailyLimitMin": 60, "sessionMin": 15, "breakMin": 15},
           {"kind": "app", "target": "com.example.blockgame", "dailyLimitMin": 90}],
 "alwaysAllowed": ["com.example.school"]}
```

- `kind`: `app` — `target` это пакет; `group` — категория Android: `video`, `social`, `game`, `audio`.
- `dailyLimitMin` — от 1 до 1440 минут в день. `sessionMin` и `breakMin` — цикл «сессия / перерыв»,
  оба от 1 до 240 и только вместе. В правиле должен быть дневной лимит, цикл или оба.
- До 50 правил без повторов `(kind, target)`; до 100 пакетов в `alwaysAllowed` без повторов.
  Любая ошибка отклоняет весь набор (`400 invalid_request`).

### `GET` и `PUT /v1/devices/{deviceId}/app-limits` (родитель)
`PUT` заменяет набор целиком и возвращает его. Чужое устройство — `404`. Лимит: 120 `PUT` в час
на семью.

### `GET /v1/device/app-limits` (телефон, `Authorization: Bearer <deviceToken>`)
Тот же формат. Пустой набор — ограничений нет.

## Запуск локально

```bash
cd backend
docker compose up -d          # PostgreSQL и Redis
./gradlew run                 # сервер на :8080 с локальным ключом шифрования
./scripts/dev-pairing-code.sh # регистрирует тестового родителя и выдаёт код привязки
```

В рабочем окружении обязательны переменные `MAXCARE_SECRET_KEY` (base64 от 32 случайных байт),
`MAXCARE_DB_URL`, `MAXCARE_DB_USER`, `MAXCARE_DB_PASSWORD`, `MAXCARE_REDIS_URL`; для входа через
Google — `MAXCARE_GOOGLE_CLIENT_IDS`.
